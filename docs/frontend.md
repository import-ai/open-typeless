# Frontend development

For local setup, debugging, and release builds, see the [development guide](development.md).

## Integration rationale

React + TypeScript + Vite + shadcn/ui were selected after reviewing the official documentation on 2026-09-28.

- [Build a React app from scratch](https://react.dev/learn/build-a-react-app-from-scratch): Vite provides a React TypeScript template. This application is a local desktop client with client-side rendering and does not need a server rendering framework.
- [Tauri Vite integration](https://v2.tauri.app/start/frontend/vite/): during development, `beforeDevCommand` starts Vite and `devUrl` loads the page. For releases, `beforeBuildCommand` builds the frontend and `frontendDist` is embedded in the application. Use a fixed port with `strictPort` to prevent connection failures caused by automatic port changes.
- [shadcn Vite installation](https://ui.shadcn.com/docs/installation/vite): use the Tailwind Vite plugin, configure the `@/` alias in TypeScript and Vite, and generate local component source with the official CLI.
- [Vite development requirements](https://vite.dev/guide/): this project uses Node 22.12+.

## Layout and conventions

Keep the existing Rust layout at `tauri-client/src/main.rs`. JavaScript dependencies, scripts, and the lockfile live in `tauri-client/`; the Vite root is `frontend/`, and build output goes to `tauri-client/dist/`.

```text
tauri-client/
  src/main.rs                 Rust commands and audio capture
  frontend/
    index.html                Single HTML entry point
    src/
      main.tsx                Selects the UI by window label
      windows/                Main window, pill, and debug preview
      components/
        recording-pill.tsx    Pill shared by production and preview
        ui/                   Primitives generated by the shadcn CLI
      hooks/                  React event subscriptions and cleanup
      lib/                    Tauri command types and utilities
      styles.css              Tailwind and shadcn theme
      pill.css                Transparency and pill-specific styles
  components.json             shadcn configuration
  vite.config.ts
  tsconfig.json
```

- Call Rust through `@tauri-apps/api` modules; do not rely on `window.__TAURI__`.
- Use React StrictMode. Clean up asynchronous event subscriptions on unmount and hot reload, including subscriptions that complete after unmounting.
- Mount only the components for the main, production pill, or debug window as appropriate. Do not use CSS to hide entire DOM trees belonging to other windows.
- Apply transparent backgrounds only to pill windows so the shadcn body background does not cover the desktop.
- Debug previews drive the same pill component with simulated volume and do not record, upload, or paste.
- Browser previews display the UI, but recording must run inside Tauri.
- Record dependency versions in `package-lock.json` and use `npm ci` for reproducible installation.

## Validation

Run `npm run build` to check TypeScript and production assets, then `npm run tauri dev` to check desktop integration.
For visual changes, also open `npm run tauri:debug` and capture screenshots; browser screenshots cannot prove native window transparency works.
